# Work Tracker — Daily Report

Розширення для обліку дзвінків, KPI, крітів і складних звернень. Поточна версія — **1.3.2**, Manifest V3.

Вихідні файли розширення розміщено у [`Daily_Report_Chrome_Extension`](Daily_Report_Chrome_Extension/). Збірка, Node.js і встановлення залежностей для використання не потрібні.

## Завантаження

1. На сторінці репозиторію натисніть **Code → Download ZIP** або клонуйте репозиторій:
   ```sh
   git clone https://github.com/zbys1av/Work-Tracker.git
   ```
2. Якщо завантажили ZIP, розпакуйте його в постійну папку.
3. Для встановлення вибирайте вкладену папку **`Daily_Report_Chrome_Extension`**, де безпосередньо лежить `manifest.json`. Не вибирайте ZIP або корінь репозиторію.
4. Після встановлення не видаляйте й не переміщуйте цю папку.

## Встановлення в браузерах на комп’ютері

Це локальне встановлення розпакованого розширення, без публікації в магазинах. Назви кнопок залежать від мови й версії браузера. Нижче наведено порядок для браузерів на Chromium; роботу в кожному з них окремо ще не перевірено.

| Браузер | Адреса сторінки розширень | Дії |
| --- | --- | --- |
| Google Chrome | `chrome://extensions/` | Увімкніть **Режим розробника / Developer mode** → **Завантажити розпаковане / Load unpacked**. |
| Microsoft Edge | `edge://extensions/` | Увімкніть **Режим розробника / Developer mode** → **Завантажити розпаковане / Load unpacked**. |
| Brave | `brave://extensions/` | Увімкніть **Developer mode** → **Load unpacked**. |
| Opera / Opera GX | `opera://extensions/` | Увімкніть **Режим розробника / Developer mode** → **Завантажити розпаковане / Load unpacked**. |
| Vivaldi | `vivaldi://extensions/` | Увімкніть **Developer mode** → **Load unpacked**. |

Після цих дій виберіть папку `Daily_Report_Chrome_Extension`. Відкрийте меню розширень на панелі браузера та закріпіть **Daily Report — Дзвінки та KPI**.

### Firefox

Цей пакет призначено для Chromium. Для пробного тимчасового завантаження на комп’ютері відкрийте `about:debugging#/runtime/this-firefox`, натисніть **Завантажити тимчасовий додаток / Load Temporary Add-on** і виберіть `manifest.json` у папці розширення. Тимчасовий додаток видаляється після перезапуску Firefox, тому не використовуйте його для зберігання робочих даних без резервної копії.

Сумісність цього пакета з Firefox не підтверджено. Для постійного встановлення у звичайному Firefox потрібні окрема перевірка сумісності, підготовка пакета та підпис Mozilla. Інструкція для Chromium не забезпечує постійного встановлення у Firefox.

### Safari

Safari не встановлює цю папку через **Load unpacked**. Потрібні macOS, Xcode, перетворення на Safari Web Extension, перевірка сумісності та налаштування підпису й розповсюдження. Готового пакета для Safari в репозиторії немає.

### Мобільні браузери

Ця інструкція стосується настільних браузерів. Chrome на Android та iOS не підтримує цей спосіб встановлення. Мобільну сумісність не перевірено.

## Перша перевірка

1. Натисніть іконку розширення: має відкритися компактне вікно.
2. Додайте тестовий дзвінок кнопкою **+1**.
3. Натисніть **Розгорнути** та перевірте, що запис відображається у повному звіті.
4. Закрийте й відкрийте вікно повторно: дані мають залишитися. Після перевірки приберіть тестовий запис.

## Оновлення та резервні копії

- Перед оновленням відкрийте повний звіт і зробіть JSON-копію через **Файл → Резервна копія (json)**.
- Оновіть файли в тій самій папці, потім натисніть кнопку перезавантаження на картці розширення на сторінці розширень браузера.
- **Не видаляйте розширення для оновлення:** видалення може стерти локальні дані.
- Дані зберігаються локально у профілі браузера через `chrome.storage.local`; автоматичної синхронізації між браузерами немає.
- Для перенесення в інший браузер установіть розширення там і скористайтеся **Файл → Відновити з копії**, вибравши JSON-копію.

## Дозволи та усунення проблем

Маніфест запитує `storage` для локального збереження `clipboardWrite` для копіювання списку з гіперпосиланнями та `downloads` для відстеження завершення конкретної локальної резервної копії. Доступу до вмісту робочих сайтів не запитує. Ресурси розширення постачаються в папці; для його основної роботи інтернет не потрібен.

- **Не знайдено маніфест:** виберіть саме папку з `manifest.json`, а не зовнішню папку ZIP.
- **Не видно іконки:** відкрийте меню розширень і закріпіть Daily Report.
- **Помилка після оновлення:** перезавантажте розширення та повторно відкрийте його вікно; перевірте повідомлення про помилки на сторінці розширень.
- **Режим розробника заблоковано:** встановлення може обмежувати політика організації; зверніться до адміністратора браузера.

Оригінальні примітки автора про функції: [`README.txt`](Daily_Report_Chrome_Extension/README.txt).

## ID, посилання та копіювання крітів (1.2.0)

У швидкому вікні й повному звіті **Посилання** та **ID** — окремі поля. Для клікабельного ID заповніть обидва: посилання у форматі `https://…` та ID кейса. Старі записи залишаються доступними: попереднє поле з URL відображається як посилання, інший текст — як ID. Якщо раніше ID та URL були записані разом одним рядком, розділіть їх вручну.

Кнопка **Копіювати кріти за тиждень (Пн–Нд)** у швидкому вікні бере поточний календарний тиждень за локальною датою браузера. У повному звіті кнопка **Копіювати тиждень (Пн–Нд)** у розділі крітів бере тиждень вибраного дня. Обидві кнопки включають понеділок і неділю, OFF-дні та записи з усіх активних аркушів, зокрема на межі місяців. Записи з різних аркушів не видаляються як дублікати.

У списку копіюються дата, бренд, ID із накладеним гіперпосиланням та опис. Вставляйте у редактор, який підтримує форматований текст (наприклад, Google Docs або Word). Звичайне текстове поле вставить ID та URL текстом. Без посилання ID копіюється звичайним текстом; без ID показується саме посилання. Порожній тиждень не змінює буфер обміну. Про помилку доступу до буфера буде повідомлено в інтерфейсі.

Перед оновленням зробіть JSON-копію. Після оновлення файлів перезавантажте розширення на сторінці розширень; браузер може попросити підтвердити новий дозвіл на копіювання. JSON-копії та повний Excel-архів зберігають обидва поля; у видимій таблиці Excel вони виводяться разом як `ID — посилання`.

Перевірка логіки (Node.js, без встановлення залежностей): `node tests/cases.test.cjs`.

## Google Drive Backup (1.3.0)

1. Відкрийте **Файл → Google Drive Backup** у повному звіті (також у розгорнутому popup). У мініверсії налаштування папки не відображаються.
2. Вставте посилання на папку й натисніть **Зберегти посилання**. Приймаються `https://drive.google.com/drive/folders/ID` та `https://drive.google.com/drive/u/0/folders/ID` (інші номери акаунтів теж підтримуються). Параметр `resourcekey` зберігається. Налаштування залишаються після перезапуску браузера.
3. Натисніть **Зберегти на Google Drive**. У папку завантажень браузера буде збережено `Daily_Report_Backup_YYYY-MM-DD_HH-mm.json`. Якщо ім’я вже існує, браузер додасть суфікс. Якщо браузер запитає місце збереження, підтвердьте його.
4. Лише після підтвердженого завершення локального завантаження відкриється збережена папка Drive. У ній натисніть **Створити → Завантажити файл** і виберіть **саме файл, названий у статусі останньої локальної копії**, або перетягніть цей файл у папку. Дочекайтеся повідомлення Google Drive про завершення.

**Рівень автоматизації:** автоматичні створення JSON, його локальне завантаження, відстеження цього завантаження й відкриття папки. Передавання файлу на Drive завершується вручну. Вебінтерфейс Google Drive не надає стабільного публічного контракту для програмного передавання файлу та підтвердження результату без API. Розширення не підставляє файли в DOM Drive, не генерує синтетичні події перетягування й не читає авторизаційні дані. Google Cloud Project, OAuth, Drive API та сервер не потрібні.

Локальна копія — той самий повний JSON-стан, що й у **Файл → Резервна копія (json)**: всі аркуші, їхні налаштування, дзвінки, OFF, кейси, річні дані, KPI, перевірки знань, кошик та інші поля. У повному інтерфейсі враховуються також останні зміни, які ще чекають автоматичного збереження. Формат JSON не змінено; відновлення — через наявну **Файл → Відновити з копії**.

Налаштування й метадані останньої копії лежать окремо у `chrome.storage.local` під ключем `daily_report_drive_backup`; робочий ключ `daily_report_v2` не змінюється. Починаючи з 1.3.2, обидві JSON-копії містять посилання на папку у `backupSettings.googleDriveFolder`. Відновлення JSON повертає його до окремого ключа налаштувань; файли без цього поля залишають поточну папку без змін. Метадані завантажень та download ID не експортуються.

Фоновий service worker відстежує конкретний download ID, тому закриття popup не припиняє завантаження. Статус останньої локальної копії оновлюється тільки після `complete`. Після скасування, помилки або відсутності папки відображається повідомлення; робочі дані не перезаписуються. Якщо Drive не відкрився, скористайтеся **Відкрити папку**. Якщо ви офлайн, не ввійшли в Google, закрили вкладку або корпоративний акаунт забороняє додавання файлів, локальна копія залишається доступною. Відновіть доступ та завантажте її вручну.

**Статус Drive завжди чесний:** відкриття вкладки та успіх локального завантаження не підтверджують передавання на Drive. Розширення показує «Не підтверджено» та не може перевірити ручне завершення. Авторизоване завантаження до реальної папки Drive в цьому середовищі не тестувалося.

Додано тільки дозвіл `downloads`; `tabs` і дозволи на сайти не потрібні для звичайного `chrome.tabs.create`. Попередні дозволи збережено. Нових content scripts та зовнішніх залежностей немає.

### Оновлення без втрати даних

Зробіть звичайну JSON-копію, закрийте повний звіт, оновіть файли **в тій самій папці**, відкрийте сторінку розширень та натисніть перезавантаження. За запитом браузера підтвердьте дозвіл на завантаження. Не видаляйте розширення. Налаштуйте папку Drive один раз.

Тести резервування: `node tests/backup.test.cjs`. Перевірено повноту JSON, адреси папок, переривання, помилки відкриття вкладки, відновлення відстеження після перезапуску service worker і останні незбережені правки (API Chrome у цих тестах імітуються).

У версії 1.3.1 збереження та читання папки працює також за недоступної фонової служби; «Відкрити папку» не залежить від неї. Якщо резервування просить перезавантаження, закрийте старі вкладки звіту, перезавантажте Daily Report на сторінці розширень (перевірте версію 1.3.1 та дозвіл на завантаження) і відкрийте звіт заново. Якщо помилка залишається, перевірте помилки service worker на картці розширення.

У 1.3.2 кнопка «Зберегти на Google Drive» винесена окремо: під підсумком тижня у мініверсії та поруч із «Файл» у повному звіті. Налаштування залишені тільки в повному звіті. Копію на Drive, як і раніше, потрібно завантажувати вручну.
